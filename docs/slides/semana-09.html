Semana 09

Chips personalizados no Wokwi

Simulando o computador de bordo sem o hardware físico

Objetivos de Aprendizado

  • Adicionar custom chips a um projeto do Wokwi
  • Ler sensores I2C por registradores (Wire)
  • Ler NMEA de um GPS por UART (Serial1)
  • Converter pressão em altitude no firmware
  • Reaproveitar o parser e a análise das Semanas 1 e 2

Por que simular?

  • Validar o firmware antes de montar a placa
  • Testar o pipeline de telemetria sem risco de queimar hardware
  • Reproduzir cenários: subida, temperatura, movimento do GPS
  • Mesmo firmware, mesmos endereços I2C e mesma UART do projeto real
chips -> firmware -> log cru -> parser -> CSV -> graficos

O que é um custom chip?

Um componente simulado escrito na Chips API (C → WebAssembly).

  • <nome>.chip.json — nome, pinos e controles (sliders)
  • <nome>.chip.c — a lógica: registradores I2C, NMEA UART etc.

Adicionando os chips

  1. Crie um projeto ESP32-S3 no Wokwi
  2. Clique no + → Custom Chip
  3. Nome bmp585, linguagem C (repita para lsm6ds3 e neo-8m)
  4. Substitua os arquivos gerados pelos do repositório
  5. Ligue os pinos e confira o Chips Console
BMP585 pronto (I2C 0x7E)
LSM6DS3 pronto (I2C 0x6B)
NEO-8M pronto: lat=-22.94 lon=-43.20 alt=700.0

Monte do zero: o diagram-exemplo.json é só conferência.

Firmware: três sensores, três caminhos

Wire.begin(8, 9);                  // I2C: BMP585 + LSM6DS3
Serial.begin(115200);              // log
Serial1.begin(9600, SERIAL_8N1, 17, 18);  // GPS
  • I2C: escreve o endereço do registrador, lê N bytes
  • UART: acumula caracteres até \n e interpreta NMEA
  • Loop a 10 Hz sem delay()

BMP585: pressão → altitude

Wire.beginTransmission(0x7E);
Wire.write(0x20);                     // PRESS_XLSB
Wire.endTransmission(false);
Wire.requestFrom((uint8_t)0x7E, (uint8_t)3);

int32_t p = buf[0] | (buf[1] << 8) | (buf[2] << 16);
float pressao = (p / 64.0f) / 100.0f; // Pa -> hPa
float alt = 44330.0f * (1.0f - powf(pressao / 1013.25f, 0.1903f));

Pressão no controle do chip → altitude calculada no firmware.

LSM6DS3: aceleração e giro

// +-2 g e 250 dps (configuracao inicial do chip simulado)
const float SENS_G   = 0.000061f;
const float SENS_DPS = 0.00875f;

// OUTX_L_XL (0x28): 6 bytes = X, Y, Z (little-endian)
ax = (int16_t)(buf[0] | (buf[1] << 8)) * SENS_G;
ay = (int16_t)(buf[2] | (buf[3] << 8)) * SENS_G;
az = (int16_t)(buf[4] | (buf[5] << 8)) * SENS_G;

Em repouso, az ≈ 1 g.

NEO-8M: NMEA do GPS

$GPGGA,000015.00,2256.60,S,04312.00,W,1,09,0.9,700.0,M,0.0,M,,*XX
  • Campo 6 = qualidade do fix (0 = sem fix)
  • Campos 2/4 = latitude/longitude em ddmm.mmmm
  • Campo 7 = satélites; campo 9 = altitude
  • Chega a 1 Hz; o pacote sai a 10 Hz com o último valor válido

Formato do pacote

16 campos, vírgula, prefixo #51:

#51,millis,pckt,alt,temp,press,gx,gy,gz,ax,ay,az,gps_alt,lat,lon,sat
#51,15234,152,540.12,25.03,950.00,0.12,-0.03,0.01,0.02,-0.01,1.00,700.0,-22.943200,-43.200000,9

Subconjunto do pacote de 24 campos do computador de bordo — mesmo parser, menos colunas.

Simular e capturar o log

  1. Rode a simulação e abra o Serial Monitor em 115200
  2. Deixe 5 minutos rodando (≈ 3.000 pacotes)
  3. Mova os controles: pressão 1013 → 950 → 800 hPa
  4. Altere a aceleração/giro e a posição do GPS
  5. Copie a saída e salve como log_wokwi.txt

Linhas [INFO] e [ERRO] podem ficar no log: o parser ignora.

Cuidados

  • O BMP585 simulado não usa a biblioteca Adafruit — leia registradores
  • Endereços diferentes do datasheet: 0x7E e 0x6B (ajustáveis)
  • UART do GPS é 9600; o monitor é 115200
  • strtok() altera a string — trabalhe numa cópia
  • Sem fix, lat/lon ficam em zero até o primeiro GPGGA válido
